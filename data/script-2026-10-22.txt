Speaking of infrastructure, there's a nice cluster on running models at scale. Google and Meta teamed up on TorchTPU, an open source PyTorch backend that makes it easier to run and migrate models on Google's TPUs. It supports both training and inference, with optimized eager execution and torch.compile integration. Then there's llm-d, a Kubernetes native stack for distributed inference. It runs engines like vLLM and SGLang across clusters, and it works across GPUs, TPUs, and other hardware, with tested deployment recipes for common production patterns. Hold onto that one, because it comes back in the IBM section.

And some big numbers from DeepSeek. A write up on DeepSeek V4.1 Flash describes a system called DeepInfer, which combines distributed inference, caching, load balancing, and speculative decoding. Next, agents, which seem to be the through line today. Vercel introduced durable harness. It lets agent harnesses like Pi, OpenCode, Codex, and Claude Code run durably, either on Vercel or on your own Postgres instance. Sessions survive crashes in the middle of a turn, and they keep running even if the browser disconnects. If a turn dies partway, it picks up from the log on a new function, with no manual retry and no repeating work that's already done.

Ramp wrote about Laminar, its in-house agent platform. It includes secure conversation history, session compaction, tool calling interfaces, message queuing and steering, subagents, multiplayer chat, and observability. The first version took six weeks with a small team of experienced engineers, and the code was generated entirely by agents. The takeaway I liked is that building in house is cheaper now, but you still need good engineers on call, keeping the platform healthy, and figuring out what product teams actually need.

Two more in that lane. Databricks described MemCurrent, a persistent memory design for production agents, and says it can triple an agent's pass rate compared to having no memory, while also making it faster and cheaper. The other item is that llm-d 1.0 was released on Tuesday. That's the same open source distributed inference project from the AI news. It was founded in 2025 by Red Hat, IBM, Google Cloud, CoreWeave, and NVIDIA, and it's now governed by the Cloud Native Computing Foundation. The pitch is that running AI at scale can be as hard and expensive as building the models. Agentic workloads keep reusing huge amounts of context, with parallel agents creating unpredictable bursts, and managing that context often costs more than generating the answer. So 1.0 aims to improve performance and throughput and give organizations more control over serving costs. It already supports mixed hardware, prefix cache and load aware routing, and KV cache offloading. That's a nice conversation starter for any client talking about AI costs.
