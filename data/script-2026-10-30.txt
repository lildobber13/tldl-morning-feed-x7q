Now the news, and there's a lot of it, so let's go.

Google has introduced Gemini 4 Carbon, a model it says improves energy efficiency while boosting performance on natural language tasks. The pitch is a smaller carbon footprint, and Google says it wants to set a new standard for eco-friendly models. A greener model is a nice thing to hear about. I'd like to see the numbers behind it, but the summary doesn't give any.

On the open side, NVIDIA released Nemotron 3.5 Transcribe, an open-weight model for multilingual transcription, translation, speaker attribution, and even audio question and answer. It supports up to 40 languages, and NVIDIA says it ranks first on several transcription and speaker attribution leaderboards. It comes with Granary v2, which offers reusable data pipelines and fine-tuning options, so you can adapt it to specialized vocabularies. For anyone who sits through a lot of meetings, that's a useful combination.

Staying with the infrastructure theme, Decagon wrote about an inference stack that improves itself. Their AutoResearch agents diagnose bottlenecks, test optimizations against replays of production traffic, and remember what they learned between experiments. They report throughput gains of up to 2.5 times within latency requirements, using quantization, scheduling, engine patches, and speculative decoding. And production changes still need a human to approve them. Good. Let the robot suggest, but keep a person holding the pen.

Next, a thoughtful piece on Artificial Analysis v5 and what it calls the benchmarker's dilemma. The argument is that independent model evaluation is hard. You want one number that matches vibe checks, community sentiment, and real science, and that still won't be stale in three months. And these evaluators help decide winners and losers in a trillion-dollar market, which also lets them steer how models get built. That's a lot of pressure on a leaderboard.

Now for something delightfully unnecessary. Someone built Qwenputer, a fully working, deterministic RISC-V CPU that runs inside Qwen3.5. It uses the model's own Gated DeltaNet layers as RAM. It can do arithmetic and run C and MicroPython code with no external runtime or tools. The developer even slotted in an experimental file storage system inside the model. Is it practical? Probably not. Is it wonderful? Absolutely.

Now the developer tools corner, which was busy. Vercel launched Vercel CI in beta, built to keep pace with coding agents. It runs only the tasks affected by a code change and spins up only the compute those checks need. Vercel says that cut the time from git push to CI pass by two to six times.

GitHub introduced Copilot Fusion, which routes and orchestrates models for each task. It builds on Project HydraFusion's multi-model orchestration and Copilot's auto model selection, balancing performance against cost. How it works depends on the level of effort the user picks, and administrators control which models it can use and whether it's the default. That admin control is the part I'd flag if you're talking to enterprise teams.

Microsoft, meanwhile, introduced the Microsoft Copilot harness. It already powers Copilot Code, Copilot Studio, the GitHub Copilot app, the CLI, VS Code, and more, and now it's available through Microsoft Foundry. It's a fully managed way to build agents that reason, use tools, and finish long-running tasks, and it's designed to work across model families. So that's two big announcements in one week about orchestrating many models. Funny how everyone suddenly agrees on the same idea.

Now for the practical agent reading list. One post, "Making agents fast," collects lessons from twelve months of work. Know which part of inference your speed depends on. Check thinking budgets and read the traces, because they often show what the agent wants to do. Give agents the tools they ask for, not the ones you assume they need. Faster hardware still matters, sandboxes and microVMs add complexity, parallelization helps, and classic performance tuning still applies.

A companion piece, "A Little Determinism," says constraints usually make agents less capable. The challenge is building predictable behavior while leaving the agent free to choose the best tools. The solution described uses a man-in-the-middle egress proxy that denies certain actions and forces reactions through automated messages. That's an agent with a very polite chaperone.

It's aimed at helping data engineering teams build, operationalize, and scale streaming pipelines running on Confluent Platform for Apache Flink. The pitch is that real-time data is now an enterprise requirement, for things like fraud detection, supply chain responses, and AI systems.
